§1 — Blocker major: TCC blochează launchd pe ~/Documents

Primul run al job-urilor (direct pe repo) a ieșit cu exit code 0 dar output gol/greșit (0 fișiere găsite, ar fi trebuit 55+). Diagnosticat cu job de test izolat:

find: ~/workspace: Operation not permitted

Root cause verificat empiric, nu presupus:

  • Terminalul (și sesiunea asta) au deja acces la Documents — de-asta rulările manuale mergeau perfect.
  • Un LaunchAgent pornit crud de launchd (fără o aplicație GUI "responsabilă" în lanțul de proces) nu moștenește acel acces.
  • Adrian a adăugat /bin/bash la Full Disk Access → tot blocat.
  • Adăugat și /usr/bin/find → tot blocat.
  • Test izolat suplimentar: rsync și cat, ambele blocate identic, indiferent de FDA.
  • Test de control: același script, citind dintr-un folder simplu din $HOME (în afara Documents/Desktop/Downloads) → merge instant, fără nicio grant.
Concluzie: pe acest build de macOS, TCC pare să evalueze fiecare binar exec-uit de un LaunchAgent independent, iar Full Disk Access pe binare individuale (bash/find) nu deblochează accesul la Documents fără o aplicație-părinte cu identitate GUI proprie deja autorizată. Nu e un bug de configurare de-al nostru — e o limitare de mediu.

§2 — Decizie Adrian: relocare scope în afara Documents

Prezentat 3 opțiuni lui Adrian (adaugă și mai multe binare la FDA / logout-login / relocare scope). Alese: relocare scope.

Arhitectură rezultată:

~/zero-workspace/
  manifests/                     ← liste plain-text (fișiere modificate ultimele 24h)
    recent_repo_files.txt
    recent_clippings_files.txt
  outputs/                       ← output-urile job-urilor (aici scrie launchd, fără restricții)
  refresh_manifests.sh           ← PRIVILEGIAT: citește din ~/Documents, regenerează manifests/
  sync_outputs_to_repo.sh        ← PRIVILEGIAT: copiază outputs/ → CLAUDE OUTPUTS/tooling/local_agent_jobs/

Important — limitare reziduală: job-urile launchd în sine rulează 100% autonom, local, fără Claude. DAR puntea către repo-ul real (refresh_manifests.sh + sync_outputs_to_repo.sh) trebuie rulată dintr-o sesiune cu acces la Documents (Terminal interactiv sau Claude Code) — nu poate fi ea însăși un job launchd, din același motiv TCC. Practic: manifestele + sincronizarea înapoi în repo cer un touch periodic manual/Claude, nu sunt "set and forget" pe termen nelimitat. Producția + verificarea (partea de model) rămân integral locale și $0 cloud.

§5 — Verifier loop (doctrina: verificator ≠ producător)

Provider nou adăugat în config Zero: omlx-verifier → model gemma-4-26B-A4B-it-QAT-MLX-4bit. Deviație de la spec (12B): gemma-4-12B-it-QAT-GGUF există pe disc dar e format GGUF — oMLX e runtime MLX-only, nu-l poate servi (confirmat: nu apare în /v1/models). 26B e singurul model MLX secundar disponibil ca verifier separat de producătorul 35B.
