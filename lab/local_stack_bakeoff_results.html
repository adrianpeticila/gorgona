Slăbiciunea tool-calling a Goose e deja documentată (S118/S119 — exact T1, ratarea subfolderelor). Rămâne fallback GUI, nu harness de orchestrare.

6. De ce Zero (raționament decizie)

  • Egalitate pe criteriul primar (5/5 fără babysitting) → se aplică tie-break-ul din spec §4: „la egalitate câștigă Zero (permission gates + exec JSON mai simplu de orchestrat)".
  • Integrare oMLX: Zero = 1 comandă, provider generic OpenAI-compatible. hermes = coupling LM Studio-nativ care a cerut proxy-shim + 3 fișiere config editate. Pentru un backend oMLX generic, Zero e drop-in; hermes e adaptare.
  • Orchestrare Faza 4: zero exec cu -o json/stream-json + permission gates granulare (write/shell/network) > hermes --yolo auto-approve. Verifier loop + launchd JOB I/O se leagă mai curat de Zero.
  • Terminare: hermes a lăsat T5 să curgă ~7min după deliverable; Zero s-a oprit la răspuns. Contează pentru joburi programate.
  • hermes nu e „pierdut": capabil (5/5), self-improving skills + cron nativ — rămâne candidat #2 / fallback dacă Zero blochează la Faza 2/4.
